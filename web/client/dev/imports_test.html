imports — every module in web/client actually parses

This is the cheapest check in the folder and it exists because the same mistake was made twice in one session. An HTML comment written inside a JS template literal must not contain a backtick — a backtick there CLOSES the string, and the file becomes a syntax error. It happened in home.js and then, an hour later, in marker_panel.js.

What made it expensive both times was not the mistake, it was the symptom. A module that will not parse does not announce itself: the suite that imports it simply never runs, so #summary stays on running… forever and the runner reports a timeout. Both times the file had to be found by hand, by importing candidates one at a time in a console.

So this imports every .js under web/client and names the ones that throw. A parse error is reported with the file that has it, in seconds, instead of as a suite that hangs. Nothing here judges behaviour — importing a module runs its top level and nothing else, which is exactly the point: it is the check that has to keep working when everything else is broken.

Needs the server: web/server/.venv/Scripts/python -m uvicorn app:app --port 8000.
