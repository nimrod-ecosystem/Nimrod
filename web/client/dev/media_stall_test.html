a video that stops, in the two modules that matter most

NOTHING MAY REQUIRE AN INPUT IN ORDER TO KEEP DOING WHAT IT IS ALREADY DOING.
Starting can need a press. Continuing must not. Some people cannot press anything.

The same hole was found in three modules on 2026-08-27. youtube.js ignored PAUSED entirely. personal.js listened only for ended and swallowed a rejected play() — the rejection a browser's autoplay policy produces for a video with sound, which is exactly what her family's recorded messages are. photos.js turned OFF its own advance timer for a video and relied on ended alone, so a stalled clip stopped the 24/7 slideshow permanently.

These drive the real modules against a real media agent, with a fake clock, and then stop the video the way a browser does — by dispatching the events a browser dispatches. play() is stubbed to reject the way a blocked autoplay rejects.

Run first: the server (uvicorn app:app --port 8000) and two agents — python agent.py --root <photos> --port 8770 and python agent.py --root <personal> --port 8771.
