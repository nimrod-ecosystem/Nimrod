the segment heartbeat

A 40-minute video was being cut off at 00:03:00, and nothing said so.

The director arms a slow backstop over whatever provider is on screen — 3 minutes of silence and it moves on — and the only thing that quiets it is segment/progress. Before this suite existed, exactly two lines in the client published that topic, both inside onPlaying. So each clip sent one beat, at the moment it started, and then went silent for as long as it played. The backstop could not tell a 40-minute video from a frozen one, and it treated both the same way.

The fix is the pattern photos.js already used: beat on a repeating signal, never satisfy on first play. An HTML5 <video> has timeupdate. The YouTube IFrame API has no such event, so the module polls getCurrentTime() and beats only when the clock has actually moved — which also makes a frozen-but-PLAYING video visible for the first time.

Run the server first (web/server/.venv/Scripts/python -m uvicorn app:app --port 8000). The personal sections additionally need the fixture agent on :8771 (web/media_agent/make_test_fixtures.py prints the command); they report themselves as NOT RUN rather than failing if it is absent.
