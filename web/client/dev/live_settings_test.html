a settings menu that does nothing

A module that declares settings and never subscribes to its own state reads its config once, at mount, and never again. Every row in its settings menu is then inert while the panel is on screen — somebody changes the wait, the volume, how long a call counts down before it answers, and nothing happens. They have no way to tell, because the menu shows the value they set. Three modules were like this and nothing was watching, so this is the thing that watches.

Found by hand: pressgame subscribed to the bus three times and to its own state not at all. The other two came from grepping for the same shape. Grep is not a check — it cannot tell a module that subscribes from a module that has the word in a comment — so this mounts every module that declares a setting, hands it a state handle it can watch, and asks whether the module took it.
