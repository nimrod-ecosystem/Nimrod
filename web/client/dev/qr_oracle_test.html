QR — module-for-module against a known-good encoder

Why this test exists. qr_test.html checks finder patterns, timing patterns, module counts and format bits — and every one of those passed while the encoder produced a symbol no phone could read. Mike pointed a phone at it and nothing happened.

Structural checks cannot catch that, because a wrong symbol has the same structure as a right one — same finders, same timing, same size. The only thing that catches it is comparing every module against an implementation known to be correct.

The fixtures in qr_fixtures.json are generated by segno (see gen_qr_fixtures.py). A single differing module is a failure, because error correction is there to survive a dirty lens, not to paper over an encoder.
