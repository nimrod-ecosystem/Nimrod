choosing a device, and falling back

For most software a microphone disappearing is a degraded experience.
For somebody whose only route to being understood runs through it, it is being cut off.

The case: a good microphone that is only there sometimes — a phone a visitor brings into the room hears far better than a webcam across it, and it leaves when they do. Both facts are normal and neither should need anybody to change a setting.

This mirrors voice.js's resolveVoice deliberately, because that file already solved the same problem for voices: store a preference rather than an id, degrade, never strand. It adds two things a voice did not need — it says which rung it landed on, and it never confuses a device going away with a person going quiet.
