can you actually add the things we describe?

Four modules were described to caregivers, ran fine in the kiosk, and could not be added from the page where you add modules. There was no error and nothing said they were missing.

Three files each carry their own list of which modules exist — kiosk.js runs them, modules.html describes them, home.html lets you add them — and the composer's picker is built from whatever happens to have been imported into that page. So a module is addable if and only if somebody remembered an import line. On 2026-08-31 comet (the module the whole aim / cursor / dwell chain exists to drive), call (the video call), pressgame and trivia were all missing.

This is the same reconcile trick modules_catalog.js already does for descriptions, pointed at reachability instead: anything a caregiver can read about must be something a caregiver can add.

It reads the real files. Importing a module list here would only test this page's own imports, which is the bug wearing a disguise — so it fetches home.html and modules.html as text and reads their import lines. Grubby, and it is the only version that actually catches what happened.
