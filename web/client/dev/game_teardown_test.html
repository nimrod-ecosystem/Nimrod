game teardown

The Stage 4 bench soak (2026-10-01) found Trivia and Word Forge each keeping about forty DOM nodes alive after every destroy, on both screen paths. The cause: each opens two state rows of its own with ctx.makeState (the shared question bank, and the lesson-routed questions), starts them polling, and never destroyed them. The runtime only disposes the handles IT made, so those kept polling every 1.5 s for the life of the page, and their subscriber closures held the destroyed panel's mount. A load that resolved after destroy could also call startPolling() and bring a destroyed handle back.

This mounts and destroys each game N times, twice over: once with every load already settled, and once destroying BEFORE the loads land and resolving them afterwards. After each, it counts what is still live: bus subscriptions, state/events handles still polling or never destroyed, setIntervals, and listeners on the mount, document and window. Every count must come back to where it started.
