writing into a folder you picked

Nimrod cannot promise "deleted after thirty days". It is not running on day thirty.

The files live in a folder on somebody's machine — that is the whole point, and it is what lets the platform server never see a byte. It is also why a retention policy enforced by a page that has to be open to enforce it would be a promise enforced by nothing. So the expiry is written into every recording, the sweep is opportunistic and described as such, and what could not be removed is reported rather than assumed away.

Nothing here touches a real disk. A FileSystemDirectoryHandle is a small, well-defined interface, so it is faked — which is the only way anything that deletes somebody's recordings should be tested.
