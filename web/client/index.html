Profiles & the module system

A profile is a device-independent container of module instances. Each instance has its own server-backed state (overwrite, versioned) and its own append-only event stream. Switch profiles and the whole dashboard swaps.

What this slice proves

  • Profiles are device-independent containers. Switch the active profile and the dashboard swaps; open the same profile in another tab and it matches (server truth).
  • Two storage kinds are locked in the schema. The counter uses overwrite state (last-write-wins + version); the press log uses append-only events that can’t be overwritten or deleted — remove the module and the config goes, the events stay.
  • Optimistic concurrency. A stale config write is rejected (409); the client rebases its keys onto the server truth and retries — no lost update.
  • Inputs stay interchangeable. The buttons, keyboard (+ – / ↑ ↓), and switch all drive the counter and the press log via one bus topic.
