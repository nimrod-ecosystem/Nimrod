Course A · Flagship

Upcycle Your Old Device

Take a phone or tablet that would otherwise sit in a drawer, open a browser, point it at one page, and put it on a shelf as a small library dashboard — a clock, the day's schedule, a rotating quote and a sourced fact, and a tap into a learning game. Nothing to install, nothing thrown away.

See the dashboard → Read the documentation
Adults & children 60 min short · 90 min long Bring a device you don't mind testing

What you need

  • An old phone or tablet with a working screen and a browser — the older the better, for the class's purposes.
  • Wi-Fi (the library's own network works).
  • A stand, easel, or anything to prop the device up — or 3D-print one from Print Your Own, once that page has real parts.
  • No account, no app store, no download.
Short version Longer version Documentation

Short version — about 60 minutes

One device, set up by the end of the hour.

  1. 0:00–0:10 — Why an old device instead of the trash: no install, no account, one web address. Open the dashboard together on the classroom's own screen first.
  2. 0:10–0:30 — Set the device's own browser home page to the dashboard address, and bookmark it. On most phones and tablets this is a setting inside the browser app, not a system setting — the instructor shows their own device's menu live rather than reading a universal set of steps, since every phone's settings menu is laid out differently.
    3. [photo: setting a browser home page — added once the class video is recorded]
  3. 0:30–0:45 — Prop the device up. Talk through what's rotating on the dashboard and why (see Documentation, below) — nothing on it is invented, everything has a source.
  4. 0:45–0:55 — From the dashboard, open Word Forge, Trivia, or Math with a single tap — the buttons on the dashboard itself.
  5. 0:55–1:00 — Take the device home, or leave it charging at a library table while the idea sinks in.

Longer version — about 90 minutes, Maker-Monday-style

Set up the device, then make the dashboard your own.

  1. 0:00–0:20 — Recap of the short version's setup, for anyone new.
  2. 0:20–0:45 — Try a second app or website as the home page instead — the dashboard is one example, not the only one. A weather site, a news reader, a favorite game: the device can be set to any of them the same way.
  3. 0:45–1:05 — Try each of the three games from the dashboard's own buttons: Word Forge, Trivia, Math. Talk through what a teacher or grandparent could reconfigure in each one — see Course E for the full documentation.
  4. 1:05–1:25 — Print a stand for the device, if the makerspace has one ready (see Print Your Own — not guaranteed to exist yet).
  5. 1:25–1:30 — Where this connects to the rest of the syllabus: the same browser, the same "point it at one address" idea, is how Courses B through E all start too.

Documentation

What this course is built on, plainly.

The dashboard

A clock, then a rotation of three kinds of content: the library's proposed session schedule, a literary quote, and a sourced fact. Every quote is a verbatim excerpt from a public-domain work — chosen over "quotes about reading," which are frequently misattributed online — and every fact carries its source. Nothing on it is invented. See the content pack.

The images

Small thumbnails from the Cleveland Museum of Art's Open Access collection — verified CC0, downloaded once and stored locally so the demo works offline and doesn't depend on a third party's server. See the credit list.

Moving between screens — checked, not assumed

The dashboard's own buttons open a game directly. Inside the wider Nimrod dashboard product (what Courses B–E use), moving between panels is done with on-screen buttons — ◂ Back, Next ▸, and ⌂ Home on a bar at the bottom of the screen — not a swipe gesture. Checked directly in the code before writing this: no swipe handling exists anywhere in the input system today. If a class expects "swipe to change dashboards," that's not what's built — say button, not swipe.

What hasn't been tested yet

No specific old phone or tablet has been tried against this page. An old Safari or Android WebView is the likeliest thing to break a promise like this, and nobody has tested that yet. This page will say "works on devices back to [X]" only after that test has actually happened — not before.
