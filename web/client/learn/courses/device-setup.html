Course C

Connect a Switch: Device Setup & Calibration

What a switch actually is, how it plugs into a browser with no special drivers, and how to tune hold time, repeat, and bounce rejection so it fits one specific hand, cheek, or head movement — taught using two games built to make the numbers visible.

Try Wait and Go → Try Comet →
Adults 60 min short · 90 min long A switch or a gamepad recommended

What you need

  • A computer with a browser — nothing to install.
  • Ideally: one USB adaptive switch, or a USB/Bluetooth gamepad — the library's own equipment, or a patron's, works the same way.
  • Without one: a keyboard's space bar is a working substitute for the class.
  • No account needed for the try-it links above.
Short version Longer version Documentation

Short version — about 60 minutes

Plug something in, see it work, tune one number.

  1. 0:00–0:10 — What a "switch" is: anything that sends one signal — a button, a head switch, a sip-and-puff tube wired to a microcontroller. To a browser, it looks like a keypress or a gamepad button. No driver, no install.
  2. 0:10–0:30 — Plug it in and open Wait and Go: hold off while a charge builds, press when the invite opens. This makes timing visible — how long a press takes, how consistent it is.
  3. 0:30–0:50 — Open Comet and drive it with the same switch — steer toward a heart, press to catch it. A second, different feel for the same input.
  4. 0:50–1:00 — Talk through what felt hard: too sensitive, too slow to register, tiring to hold. That conversation is the actual point of the hour.

Longer version — about 90 minutes

Tune a switch to a specific person.

  1. 0:00–0:15 — Recap, then a broader look at input types: switches, gamepads, eye-gaze-to-keypress bridges like Ace Centre's EyeCommander, and plain keyboards.
  2. 0:15–0:45 — Both games, played twice each: once with default timing, once after adjusting hold time and repeat delay by hand in the settings. Compare how the second pass feels.
  3. 0:45–1:05 — Bounce rejection and stuck-switch handling: what they're for, and why a switch that "sometimes double-fires" or "sometimes doesn't register" is almost always a timing setting, not a broken switch.
  4. 1:05–1:20 — Group discussion: for a specific access need described by the class, which of the two games' feel matched it best, and why.
  5. 1:20–1:30 — Where this connects to Course B: the exact same switch drives the AAC board's scanning mode.

Documentation

What this course is built on, plainly.

The device bus

One shared layer that any switch, button, dial, or controller plugs into. Whatever it is, the browser sees a keypress or a gamepad input, and the bus turns that into a named action — next, select — that any module can bind to. Set it up once; it works the same on every screen.

Wait and Go

A go/no-go timing task: hold off while a charge builds, press when the invite opens. It records every press and release with real timing — including presses the game itself ignored — as a measurement, not just a score.

Comet

A comet that follows the switch's steering exactly, with hearts to catch by pressing. Movement maps one-to-one to input, so cause and effect are unmistakable — useful both for teaching and for a caregiver watching whether a person can reliably affect something on screen.

An honest limit

Calibration doesn't read the numbers back yet. Wait and Go and Comet both produce real timing data, but nothing in the product turns that data into a suggested hold-time or scan-speed setting automatically — an instructor tunes those settings by hand, watching the same numbers a patron just produced. That's a real gap, not a course simplification, and this class teaches the hand-tuning skill that fills it today.
